# dexe_robot_server 动力学参数辨识

本文说明 [`script/dyn_params_ident/`](../script/dyn_params_ident/) 和 [`script/qt_dyn_params_ident.py`](../script/qt_dyn_params_ident.py) 实现的双臂动力学参数辨识流程、数学原理、操作步骤及结果验证方法。

## 1. 目标与产物

动力学参数辨识的目标是根据机器人执行激励轨迹时采集的关节运动和力矩数据，求出符号动力学模型中的最小参数集 `β`：

```text
τ = Y(q, dq, ddq, g) · β
```

其中：

- `q`、`dq`、`ddq` 分别是关节位置、速度和加速度。
- `g` 是 DH 基坐标系中的重力方向。
- `Y` 是对动力学参数线性的回归矩阵。
- `β` 是最小动力学参数集，包括惯性、质量与质心组合、驱动惯量、库仑摩擦、黏性摩擦和摩擦偏置。

辨识结果写入运行配置：

| 手臂 | 配置字段 |
|---|---|
| 左臂 | `dyn_base_params_primary` |
| 右臂 | `dyn_base_params_secondary` |

运行时，[`inverse_dynamics_symbol.cpp`](../robot_server_lib/dynamics/inverse_dynamics_symbol.cpp) 将这些参数代入对应机器人版本的符号函数，计算双臂逆动力学前馈力矩。

## 2. 工具分工

| 文件或目录 | 作用 |
|---|---|
| [`script/qt_dyn_params_ident.py`](../script/qt_dyn_params_ident.py) | 提供 GUI，完成 ROS 连接、仿真检查、真机采集、滤波与差分、参数求解、结果验证和配置写入 |
| [`script/dyn_params_ident/urdf2dh.py`](../script/dyn_params_ident/urdf2dh.py) | 从 URDF 关节轴和坐标系计算左右臂标准 DH 参数、工具变换及 DH 基坐标系中的重力方向 |
| [`script/dyn_params_ident/traj_generator.py`](../script/dyn_params_ident/traj_generator.py) | 在关节限制与碰撞约束内生成多谐波激励轨迹，并输出位置、速度和加速度检查图 |
| [`script/dyn_params_ident/dyn_code_generator.py`](../script/dyn_params_ident/dyn_code_generator.py) | 使用 SymPyBotics 生成各机器人版本的回归力矩函数和质量矩阵函数 |
| [`script/dyn_params_ident/trajectories/`](../script/dyn_params_ident/trajectories/) | 按机器人版本和左右臂保存 `traj1.dat`、`traj2.dat` |
| `script/dyn_params_ident/recdata/` | 保存真机执行轨迹时采集的关节位置与力矩数据 |

常用入口：

```bash
./set_w1.sh dyn
./set_w1.sh trajgen
./set_w1.sh dh
./set_w1.sh codegen
```

## 3. 建模原理

### 3.1 几何模型

[`urdf2dh.py`](../script/dyn_params_ident/urdf2dh.py) 从当前运行配置获取机器人类型、版本和 URDF 路径，然后分别处理左右臂：

1. 找到手臂基座到末端的活动关节链。
2. 将 URDF 中的关节轴与原点转换为标准 DH 参数。
3. 计算 DH 基坐标系与 URDF 坐标系之间的变换。
4. 将重力向量转换到左右臂各自的 DH 基坐标系。
5. 对若干关节姿态比较 DH 正运动学与 URDF 运动学，检查转换结果。

机器人几何、关节轴或基座坐标系变化后，应重新检查 DH 参数；不能直接沿用旧版本的符号模型和辨识参数。

### 3.2 参数线性化

GUI 中的 `DynParamCalculator` 使用 SymPyBotics 建立 7 自由度手臂模型，并启用：

- 刚体惯性参数；
- 简化驱动惯量；
- 库仑摩擦；
- 黏性摩擦；
- 摩擦偏置。

完整动力学参数存在相关性，不能全部由关节力矩独立辨识。SymPyBotics 通过参数基变换提取最小参数集，使每个采样点满足：

```text
τ[k] = Y[k] · β
```

将全部采样点纵向堆叠后得到：

```text
ω = W · β
```

其中 `W` 是整段轨迹的回归矩阵，`ω` 是按采样时刻和关节展开的测量力矩向量。

## 4. 激励轨迹

[`traj_generator.py`](../script/dyn_params_ident/traj_generator.py) 生成非重复、多谐波关节轨迹。轨迹需要同时满足两个目标：

1. 充分激励不同动力学项，使回归矩阵具有较好的可辨识性。
2. 满足关节位置限制、速度约束和碰撞约束，能够安全地在真机执行。

每个机器人版本的左右臂各保留两组轨迹：

| 轨迹 | 用途 |
|---|---|
| `traj1` | 构造求解数据，计算最小参数集 |
| `traj2` | 不参与求解，用于独立验证预测力矩 |

生成新轨迹后必须先检查轨迹曲线，再通过 GUI 在仿真环境完整执行。确认关节范围、运动速度、双臂间距和周边碰撞风险后，才能用于真机采集。

## 5. 真机数据采集

启动 GUI：

```bash
./set_w1.sh dyn
```

GUI 通过 ROS 2 与真机和仿真接口通信，主要使用关节位置控制 Topic、机器人状态 Topic 和 `SetProperty` Service。完整采集会让左右臂分别执行 `traj1` 和 `traj2`。

默认采样周期为 `0.01 s`。每个采样点记录：

- 关节位置；
- 电流估算力矩 `joint_torque`；
- 关节力传感器力矩 `joint_torque_sensor`。

当前求解使用电流估算力矩；传感器力矩用于曲线显示和结果对比，不进入回归方程。

真机采集前应：

1. 确认机器人反馈在线、无电机错误且能够正常清错。
2. 在仿真中完整执行两组轨迹。
3. 清理机器人周围空间，人员离开双臂运动范围。
4. 先使用低速设置验证单臂，再执行完整双臂采集。
5. 保留原始采集文件，避免只保存处理后的数据。

## 6. 数据预处理

`process_regression_data()` 对 `traj1` 和 `traj2` 使用相同的处理链：

1. 对原始关节位置执行三阶 Butterworth 零相位滤波。
2. 使用中心差分从位置计算速度。
3. 再次差分得到加速度，并分别对速度和加速度滤波。
4. 当前对电流估算力矩不额外低通滤波。
5. 裁掉轨迹开始约 3 秒和结束约 1 秒的数据，减少起停过渡影响。
6. 根据每个采样点的 `q`、`dq`、`ddq` 生成回归矩阵。
7. 对回归矩阵执行 QR 分解，为后续约束优化构造数值问题。

差分会放大位置噪声，因此滤波参数、采样周期和时间戳稳定性会直接影响辨识结果。改变轨迹基频或采样周期时，应同步复核截止频率与裁剪区间。

## 7. 带物理约束的参数求解

辨识使用 `traj1`，求解目标可概括为：

```text
minimize    ‖W · β - ω‖²
subject to  惯性参数物理可行
            驱动惯量和摩擦参数为正
            质心位于给定连杆包围盒内
            总质量不超过设定上限
```

实现并非直接使用无约束最小二乘，而是将残差目标和物理约束写成线性矩阵不等式（LMI），通过 `lmi_sdp` 转换为 SDPA 稀疏格式，再调用 `dsdp5` 求解。

物理约束的作用是避免仅在采集轨迹上拟合良好、但对应负质量或非正定惯性矩阵的参数。约束中的连杆质心包围盒和整臂最大质量是代码内的先验值；机器人机械结构发生明显变化时，需要同步审查这些范围。

## 8. 结果验证

参数求解后执行两类验证。

### 8.1 质量矩阵正定性

工具随机采样 10,000 组关节位置，将辨识参数恢复到动力学模型并计算质量矩阵 `M(q)`，再通过 Cholesky 分解检查其是否正定。只要出现非正定样本，本次结果就判为失败。

该检查验证模型是否具有基本物理可行性，但不能代替力矩精度验证。

### 8.2 独立轨迹验证

`traj2` 不参与参数求解。工具使用辨识结果计算：

```text
τ_pred = W_traj2 · β
```

并对比：

- 预测力矩；
- 电流估算力矩；
- 关节力传感器力矩；
- 预处理后用于辨识的力矩。

应重点检查各关节的系统性偏差、相位差、速度换向处摩擦误差以及峰值力矩误差。仅凭 `traj1` 拟合曲线不能判断参数可用，必须查看 `traj2` 的独立验证结果。

## 9. 写入配置与代码生成

验证通过后，GUI 可写入：

```text
~/dexe_robot_server_data/robot_config.yaml
```

写入位置由当前配置中的 `robot_type` 和版本前缀确定。左臂更新 `dyn_base_params_primary`，右臂更新 `dyn_base_params_secondary`，重启服务后生效。

参数写入前应备份原值并保存：

- 机器人类型与版本；
- 使用的 `traj1`、`traj2`；
- 原始采集数据；
- 滤波和采样参数；
- 辨识结果与验证图；
- 真机验证结论及回滚参数。

如果只是重新采集同一几何模型的数据，通常只需重新辨识参数。如果 URDF、DH 参数、动力学参数定义或机器人版本发生变化，则还需要运行：

```bash
./set_w1.sh codegen
```

该命令调用 [`dyn_code_generator.py`](../script/dyn_params_ident/dyn_code_generator.py)，为对应版本生成回归力矩函数和质量矩阵函数。生成代码应与运行配置中的参数维度和顺序保持一致。

## 10. 推荐操作顺序

1. 确认运行配置、URDF、机器人版本与真机一致。
2. 检查或重新生成 DH 参数和重力方向。
3. 生成 `traj1`、`traj2`，检查限制与碰撞。
4. 在仿真中分别执行左右臂两组轨迹。
5. 低速执行单臂真机采集，再执行完整采集。
6. 使用 `traj1` 求解左右臂参数。
7. 通过质量矩阵正定性检查。
8. 使用 `traj2` 检查预测力矩与实测力矩。
9. 备份配置后写入辨识结果并重启服务。
10. 低速验证位置模式和力矩控制相关模式；异常时立即恢复原参数。

## 11. 依赖与常见问题

辨识与代码生成依赖 SymPyBotics、`lmi_sdp` 和 DSDP5。安装方式及 `lmi_sdp` 与 SymPy 版本兼容问题见：

```text
script/dyn_params_ident/README.md
```

若求解失败或结果不稳定，应依次检查：

1. 采集文件是否完整，采样周期是否稳定。
2. 轨迹是否充分激励所有关节。
3. 关节位置与力矩列是否对应正确。
4. DH 参数、重力方向和左右臂选择是否正确。
5. 起止段裁剪与滤波参数是否适合当前轨迹。
6. 物理约束范围是否与当前机械结构匹配。
7. `traj2` 独立验证是否存在明显系统误差。
